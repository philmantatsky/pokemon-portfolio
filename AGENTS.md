# Pokemon Portfolio — AGENTS.md

React + Vite portfolio site styled as a Pokemon Platinum DS battle sequence.

## Stack

- React + Vite
- CSS Modules
- `Press Start 2P` font (loaded via Google Fonts in `index.html`)
- No external state library — plain `useState`

## Running

```sh
npm run dev
```

## Screen Flow

```
start → select → battle → portfolio
```

`App.jsx` controls the screen via `useState('start')`. Each screen is a top-level component.

Here's my portfolio, I guess." — advancing calls `onFinish()`. Enemy HP box is hidden during `outro` too (fainted Pikachu stays at opacity 0 under him)

Two lines: "You are challenged by PHILLIP!" then "PHILLIP: If you wanna see my portfolio, you'll have to defeat me in battle!". Trainers slide in on mount (`trainerInLeft/Right`) and slide out (`trainerExitL/R` classes, 550ms; phase flips to `intro` + enemy ball timers start 600ms later via `advanceDialog`). HP boxes and the enemy Pokéball are gated on `phase !== 'trainerIntro'`. The Trainers (Back) sheet has 4 more Ethan throw frames + Lyra/Silver/Lance etc. if a throw animation is ever wanted

  - HP drain: the bar width animates via one CSS `width` transition (`enemyBarPct` 100→0 over `DRAIN_MS`, inline style) for smoothness; the `enemyHp` interval remains but only drives the green/yellow/red threshold classes and the faint-timing callback — don't route the width back through it or the bar steps
  - Attack FX (`.fxLayer` in Battle.module.css) use **authentic Game Freak battle-anim sprites** from the pret/pokeemerald decomp (`graphics/battle_anims/sprites/`, palette index 0 → transparent, saved as `src/assets/fx-*.png`); choreography matched to Bulbagarden APNG recordings of the Gen IV animations (do NOT overlay those APNGs directly — they're full 256×192 screen recordings with the wrong Pokemon/UI baked in). Frame strips are vertical and stepped via `background-size: 100% N00%` + `animation: steps(N, jump-none)` over `background-position-y` 0→100%. Per type: FIRE = 3 glowing `emberBall`s (fx-ember) arc over, then `fireBurn` — the REAL Gen IV Ember flame, extracted frame-by-frame from the Bulbagarden DPPt recording by chroma-keying fire colors (fx-fire.png, 12-frame 40×80 vertical strip; extraction: pixels with r≥180, r−g≥22, r−b≥95 in the flame region of `Ember_IV.png` frames 2–13; later frames are contaminated by the target sprite) — plays once over the enemy + 3 CSS smoke puffs. Both a smooth CSS-gradient flame ("egg-like") and the pokeemerald bonfire sprite were rejected by the user — the extracted DS frames are the approved look; WATER = HGSS style per the user's Buizel reference: 10 soft mist puffs (fx-mist + white glow) stream mouth→enemy, then `waterBurst` — a big glowing white radial-gradient water mass with wispy tip + side puff (pseudo-elements) — swells over the enemy on the platform, with 8 sparkling CSS `waterDrop` specks (no hard starburst/splash-crown sprites — user rejected those); DRAGON = HGSS Dragon Pulse style per the user's reference: `pulseRing` (purple aura ring) + `pulseCore` (white glow) charge at the player's mouth, 7 growing `pulsePuff` mist clouds (fx-mist) stream to the enemy, `pulseCloud` smoke cluster (main + 2 pseudo-element side puffs) bursts on its body; GRASS = 6 spinning CSS leaves + green burst (user likes this one — keep); DARK = white zigzag fang rows (`clip-path`) + flash. Scene anchors: player mouth ≈ (28%, 40%), enemy center x = 77.5%, enemy feet = bottom 51%. FX render while `projectile` state is set (cleared after 2200ms); NORMAL moves get lunge+hit only
  - Controls: arrows move cursor, Z/Enter/Space confirm, X/Esc/Backspace cancel, everything clickable; dialog advances on click/key with blinking ▶
  - Layout mimics the DS two-screen split: the dialog box lives at the BOTTOM OF THE SCENE (top 60%) and stays visible during menus showing "What will X do?"; the bottom panel (lavender, pokeball decoration strip) is the DS bottom screen holding the menu / move grid, or empty during dialog

  - Scene: player Pokemon lower-left, slightly bigger than the enemy for perspective (`clamp(160px, 19vw, 240px)` vs enemy `clamp(130px, 15.5vw, 190px)`); its feet line (21%) sits BELOW the dialog top (~26%) so the dialog box crops the feet and the body meets the border directly (HGSS reference); its mound is mostly behind the dialog; enemy on a platform upper-right. Platforms are the AUTHENTIC HGSS grass battle bases (ripped from the Spriters Resource "Battle Bases" sheet, asset 41996): transparent PNGs in `src/assets/` — `base-enemy-grass.png` (126×32 full ellipse, tan rim + tuft fringe) and `base-player-grass.png` (204×30 wide arc, flat bottom meant to be cropped by the dialog). Stretched non-uniformly via `background-size: 100% 100%` + `image-rendering: pixelated`, like the DS perspective squash. HP boxes are large and attached flush to the screen edges (enemy left, player right) with gender symbols (player ♂ blue `genderM`, Pikachu ♀ red `genderF`), teal `Lv`, orange HP pill; player box shows 20/20 (~real Lv5 starter HP) plus an unlabeled segmented EXP strip (`expRow`/`expTrack`/`expFill`, DPPt style) hanging BELOW the box (`top: 100%`, `left: 12px` — starts slightly INSIDE the box's left edge, user-tuned) with tick-mark breaks (`expTrack::after` repeating-linear-gradient over fill + empty track) — it sits at `EXP_FROM_PCT` (20%) and CSS-transitions to `EXP_TO_PCT` (65%) when the "gained X Exp. Points!" victory line appears (effect on `phase`/`lineIdx` in Battle.jsx). The player box sits at bottom 31% specifically so the box + hanging strip clear the dialog's outer border (top ≈ 27.5%) — lower and the dialog covers the strip; enemy shows no numbers
  - `.selected` (red selection ring) must stay LAST in Battle.module.css — it competes with the buttons' own box-shadows at equal specificity
  - Dialog repaint bug: Chromium under-invalidates old `Press Start 2P` glyphs when the dialog string changes, leaving stale glyph tops above the new text (worse while the ▶ arrow blinks). Fixed by a `useLayoutEffect` on `dialogText` in Battle.jsx that toggles the dialog box `display: none` → `''` (forced reflow). CSS-only attempts (compositor layer promotion, paint-rect padding, element `key` swap) do NOT fix it — don't re-try them
  - Sprite positioning: sprite PNGs carry transparent padding below the feet (differs per Pokemon). Sprites are anchored by FEET line: `bottom: calc(<feet-line%> - <pad-fraction> * clamp(<sprite-width>))`, horizontally centered on platforms via `calc(<platform-center%> - half-width)`. Player pad comes from the `--backPad` CSS var set in JSX (`BACK_SPRITE_PAD` for HGSS backs: Bulbasaur 0.225, Charmander 0.138, Squirtle 0.15); HGSS Pikachu's 0.175 is hardcoded in CSS. If sprites change, re-measure padding from the PNG alpha channel (canvas trick in browser)
  - Scene extras: posterized sky bands tighten toward a warm horizon glow, banded grass with center arena glow, authentic HGSS battle-base platforms, contact-shadow ellipses under both Pokemon

- **Portfolio** (`src/components/Portfolio.jsx` + `Portfolio.module.css`) — the DPPt "Choose a Pokémon" party screen, reached after the battle outro. Six projects as party slots; `onExit` returns to the start screen so the sequence can be replayed.
  - `PROJECTS` const at the top of the file holds **placeholder** entries — real names/summaries/links still need filling in. `lv` + `hp` are decorative (the bar is always full and green, per the reference). Dropping `url` or `github` from an entry removes that row from its menu, and the cursor bounds follow the rendered list automatically. Keep it at 6 — the layout is the party screen and does not scroll
  - Layout: two flex columns (even indices left, odd right), `.colRight` padded down ~5vh for the reference's stagger, `justify-content: center` so the slots fill the height without a dead band above the dialog. Slots are **fixed-height** (`clamp(104px, 22vh, 178px)`) — letting them `flex: 1` leaves a blue void between the HP bar and the Lv row
  - Slot internals are a grid (`'ball name' / 'ball hp' / 'lv num'`): CSS-drawn pokéball (no asset) **tilted `rotate(-20deg)`** and **straddling the panel's left border** (`justify-self: start` + negative `margin-left`, like the reference balls poking past the edge), with the party mini icon as a **sibling of `.ball`** anchored to the slot (`left: calc(var(--ballCol) * 0.16)`, `top: ~-10px` so it overhangs the panel's top edge and stays upright — inside the ball it would rotate along), outlined white name, HP bar per the reference: **italic red `HP` pill with a pale `#f2f2f4` rim over a dark outline** (border + box-shadow), tucked into a **fully-rounded black capsule track** (`border-radius: 999px`, left end hidden under the pill via negative margin) with a two-tone green fill + white end-cap tick (`hpTrack::after`), `Lv.{lv}` bottom-left (WITH the period) + big HP numbers bottom-right (same scale as the name, per the reference)
  - **Styling matches the user's DPPt party-screen screenshot (supplied 2026-08-24; supersedes the earlier "desaturated" pass).** Still flat-DS: no gloss, hard colour stops only. Backdrop is **flat dark slate** (`#4b5266`) — the pinstripes are NOT a global texture: each COLUMN has **ONE continuous pinstriped box** behind all its panels (`.colInner::before`; `.colInner` is a content-sized wrapper div inside `.col` so the box spans first slot → last slot; offsets top ~+12px, left ~-14px, bottom ~-16px, right ~+8px = tucked under on top/right, peeking out down-LEFT toward the screen edge / centre gap; `repeating-linear-gradient` `#6a7288/#232a3a`, `z-index: -1`). The user asked for the stripes to "connect" into one box — an earlier per-slot `.slot::before` version read as disconnected rectangles in the gaps and was replaced. **Stacking gotcha:** `.party` has `isolation: isolate` so those negative-z shadows paint above the screen backdrop but below every panel; do NOT give `.slot` its own `z-index`/stacking context — that puts the striped `::before` ABOVE that slot's background and the stripes cover the panel (verified). Keep the shadow stripe colours high-contrast — tones that average to the backdrop colour vanish. Panels are **completely flat two-tone** (`#84a2ec 0 42%, #5677d2` — the lighter band is the "shading near the name" and that's it; the user rejected dense 2px/2px scanlines AND the later sparse-lines pass — no line overlays at all); selected slot = `#b6e0f2/#90c9e2` cyan (a brighter first pass was rejected as "far too bright") + **RED** `#d83010` border/ring (user: "red not orange" — `#f07818` is superseded), and on select/hover its **ball pops OPEN** (`.slotOn .ball`: the element becomes the pale white bowl nudged into the panel's top-left corner, `::before` the pink lid half-disc swung up-left, `::after` the gray opening rim — replaces the base glint/button pseudos). Pokéball is classic saturated red (`#e04a3c` top, hard-edged `#f8b8b0` pixel glint via `.ball::before`)
  - **Portfolio font is the real DPPt face, not Press Start 2P**: `src/assets/pokemon-ds-font.ttf` ("Pokémon DS Font" fan recreation by sergalbutt, fetched from the `boranblok/PokemonRomTools` GitHub repo via jsDelivr), declared via `@font-face` as `'Pokemon DS'` at the top of `Portfolio.module.css` and applied to names/Lv/HP numbers/HP pill/dialog/CANCEL/action menu with `'Press Start 2P'` as fallback. Its caps are small relative to the em — **sizes run ~2× what Press Start 2P needed** (name `clamp(26px,3.6vw,46px)`, Lv/numbers `clamp(24px,3.4vw,44px)`, dialog/CANCEL `clamp(24px,3vw,38px)`), with **8-direction** 3px navy outlines (diagonal-only text-shadows leave gaps on cardinal edges and the glyphs read broken — user flagged it) and `letter-spacing: 3px` on name/Lv/numbers (the outline eats the font's tight side bearings; 0 tracking merged the letters and the user flagged it — 3px restores the reference's gaps). DPPt dialog/menu text is **dark gray `#4c4c54` + pale `#c8c8cc` drop shadow**, not black. Battle/start/select screens stay on Press Start 2P
  - `.cancelBtn.slotOn` must re-declare `background` + `border-color`; otherwise the generic `.slotOn` (same specificity, later in the file) paints the CANCEL key with the cyan slot fill
  - State machine: `browsing → actions` (context menu: SUMMARY / VISIT / GITHUB / CANCEL). SUMMARY writes the project's blurb into the bottom dialog box rather than opening a second screen; VISIT/GITHUB `window.open(..., 'noopener,noreferrer')`
  - The context menu canNOT use the `::before { inset: -8px }` double-border trick: it needs a `z-index` to clear the sprites, which makes it a stacking context, and the negative-z `::before` then paints **over** the inner border instead of behind it. It uses `box-shadow: 0 0 0 8px #fff, 0 0 0 12px #1a1a1a` instead. The portfolio `.dialogBox` no longer uses the `::before` recipe at all — per the DPPt reference it's the **tan-framed message box**: 4px `#55565e` inner border + box-shadow rings (`#b9aa80` tan band, `#57493a` brown outline), a frame around the box, NOT a full-width tan strip; CANCEL floats beside it on the slate with a thin light rim (the Platinum double border stays on the battle screens)
  - Buttons keep DOM focus after a mouse click and the UA focus ring reads as a second selection marker, so `:focus { outline: none }` — the orange cursor ring is the only indicator
  - Slot icons are the chunky **party mini icons**: `src/assets/icon-{id}.png` (Gen VII menu icons, PokeAPI sprites repo via jsDelivr `sprites/pokemon/versions/generation-vii/icons/{id}.png` — same style lineage as the DPPt party icons).
